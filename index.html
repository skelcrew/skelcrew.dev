The problem

Agents got good. Supervising them didn't get easier.

Coding agents can do real work now, but each one still needs a person in a chat window, approving steps and reading every line. Run three at once and your day becomes switching between them.

That doesn't scale, and it wears people out. Developers get faster, but not better off. The bottleneck has moved from writing code to deciding what to build, checking the result, and keeping track of it all.

How it works

The task is the unit of work, not the chat.

You add a task. A small crew with clear roles takes it from there.

  1. 01

    You add a task

    From the command line, or pulled from your tracker. One sentence is enough.

  2. 02

    Planner triages

    Decides how much care it needs, and whether it should ship, stay a prototype, or just answer a question.

  3. 03

    Builder builds

    Works in its own isolated workspace, with your project's rules and tests.

  4. 04

    Tester reviews

    A separate agent reviews adversarially and collects evidence. Up to three rounds.

  5. 05

    You get the result

    A branch, a pull request or a report. Critical changes wait for your sign-off.

Parallel and unattended

Agents keep working while you're away. Set how many run at once, and let them go.

Decisions, not supervision

When an agent needs you, it asks a short question with options. You can still step into any session and talk to it.

Plumbing, not another AI tool

No IDE, no lock-in. Skelcrew runs the agents you already use and hands their work to git, GitHub and your tracker.

Why you can leave it running

Guarantees in code. Judgment in agents.

Agents propose. A small, deterministic core decides what's allowed, by fixed rules. An agent never holds the power to break them.

01

No agent approves its own work

Building and reviewing are separate roles. Nothing ships without review, and no agent can start more agents than you allow.

02

Nothing ships unchecked

The work that passed review is exactly the work that gets delivered. Changes to critical code wait for you.

03

Everything is on the record

Every step is an event in an append-only log. See exactly what happened and why, and replay it.

04

Nothing is lost

Work is saved before an agent is stopped. A crash or restart picks up where it left off.

Built to stay small

If the next model is twice as good, does this become dead code?

That's the test for every feature. If the answer is yes, it isn't built. Skelcrew doesn't try to make agents smarter. It runs vanilla agents and stays out of their way, so it gets better with every model instead of being tied to one vendor.
